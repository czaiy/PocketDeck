# KZQ PC Remote —— 手机控制电脑一体化控制台

手机浏览器扫一扫，控制 Windows 电脑：**触控板 / 键盘 / 语音输入 / 关机重启锁屏 / 切换显示器 / 音量媒体键 / 虚拟桌面**，全部功能集成在一个网页控制台里。

## 快速开始

1. 电脑双击 `start.bat`（首次已配好 `.venv`；换机器时先 `python -m venv .venv` + `.venv\Scripts\pip install -r requirements.txt`）
2. 自动弹出二维码页面；手机与电脑连**同一个 Wi-Fi**，用手机浏览器扫码打开
3. 连接成功顶部显示「已连接」，开始使用

> 首次运行若弹出 Windows 防火墙提示，勾选「专用网络」并允许访问。

## 功能说明

主界面只有三样：**输入框（置顶）→ 按钮行[遥控模式 | 常用键 | ☰ 更多] → 大触控板（占满剩余空间）**。

## 遥控模式（手机当电视遥控器）

「遥控模式」按钮开启后，弹出与「常用键」同款的**遥控浮层**（玻璃质感、按钮同尺寸 44px、面板同高，浮在触控板上方、不占满，触控板手势保留）：

默认面板只保留 3 行核心九键：`返回 / ↑ / 拖拽`、`← / OK / →`、`⌫ / ↓ / Tab`，尺寸与「常用键」面板一致。导航状态条与「区域 / 模式 / 焦点」高级入口保留在 DOM 中，但当前默认隐藏。

## 三层导航架构（语义 → 区域 → 空间）

方向键不是「把整棵无障碍树铺平成焦点」，而是按优先级取能拿到的最可靠语义：

| 优先级 | 层 | 数据来源 | 何时使用 |
|---|---|---|---|
| 1 | **网页语义层（DOM）** | Chromium DevTools Protocol + 页面内 `nav_helper.js` | 浏览器窗口且调试端口可用（精度最高） |
| 2 | **Windows UI Automation** | UIA 控件树 | 非浏览器应用 / 浏览器没开调试端口 |
| 3 | OCR + OpenCV | 截图识别 | 可选层，未安装时静默跳过 |

**同一时刻只有一个层产生焦点**，DOM 掉线才降级 UIA，不叠加。OCR 层永远不替代 DOM 已能拿到的控件信息。

### 1. 语义优先：只认「真控件」

候选白名单（ARIA role）：`button / tab / textbox / searchbox / combobox / menuitem / checkbox / radio / switch / slider`。
链接默认**不参与**，只有 Profile 指定 `link_zones`（顶栏/侧栏）时才收；正文链接、推荐位链接一律不进。

排除：正文段落、标题、正文文本、图片、视频画面、评论区、推荐位、广告、装饰元素、隐藏（`display:none` / `visibility:hidden` / `aria-hidden` / `inert`）、禁用、被遮挡元素。

每个候选都要过：**可见性 → 交互性 → 视口内 → 遮挡（三点 `elementFromPoint` 命中测试）→ 所属区域合法 → 去重（嵌套同类只留内层）**。

### 2. 区域导航：方向键只在当前区域里走

七个区域：`TOPBAR / SIDEBAR / MAIN / COMPOSER / DIALOG / PLAYER / SEARCH`。
每个区域各自维护候选集；方向键优先在当前区域内找目标。UIA/原生窗口在智能模式下，区域到边或区域为空时按几何**自然跨区**；浏览器 DOM 语义层仍优先区域锁。弹层/菜单保持围栏，不跨区兜底。

- **顶栏/侧栏/底栏识别**用「承载条带容器」的几何（元素自己只有 60px 宽，判不出它是否落在横跨整屏的顶栏里，这是之前的错因）
- **搜索框**按语义优先归 `SEARCH`（即使在顶栏里）
- **输入区（COMPOSER）** 按功能组顺序：`附件 → 工具 → 输入框 → 语音 → 发送`，站点缺哪个就跳哪个，绝不凭空补按钮
- **弹窗**：检测到 `[role=dialog] / dialog[open] / [aria-modal]` 自动切到 `DIALOG`，候选只剩弹窗内的控件（围栏）；关闭后自动恢复原区域与焦点（用**稳定 key** 重绑，不是 DOM 引用）
- **显式切区**：`区域 ◀ / 区域 ▶` 循环切到有控件的区域，落到该区第一个控件

### 3. 空间导航：区域内按几何 + 语义挑「下一个」

参考 WICG css-nav-1：
- 先按方向**过滤反向目标**（`fwd <= 0` 不算）
- **45° 方向锥**：副轴完全分离且中心偏出锥外的斜角目标不算
- **同行/同列硬约束**（关键）：水平移动时目标垂直中心偏移超过起点高度 1.2 倍直接不是候选，0.75~1.2 倍重罚。没有这条，从一行最后一个按钮按右键会斜着跳到下一行中间的滑块——正是用户说的「焦点乱跳」
- 同轴重叠优先、同功能组优先、远距离严格惩罚（超半视口陡增，超一视口不跨区）、可编辑控件略优先
- 区域内没有合适候选 → UIA/原生窗口在智能模式下按几何自然跨区；DOM 语义层仍优先区域锁。状态条如未隐藏会给出原因（`zone-empty` / `zone-end` / `group-end`）

### 4. 编辑态：方向键归输入框

焦点在真可编辑控件（非只读 `Edit`、`contenteditable`、编辑器特征词命中）时，**方向键原样发给应用**（移文字光标/滚动页面），不抢焦点。DOM 层和引擎层各判一次，任何调用路径都绕不过去。

想在输入框里往外跳：按 **Tab**，或**长按方向键**（连发段带 `force`），或切**自由模式**。

### 5. 三种模式

| 模式 | 行为 |
|---|---|
| **智能**（默认） | 编辑态交给输入框，其余按区域锁 + 空间导航 |
| **区域** | 强制只在本区走，不做编辑态让权（纯 TV 式操作） |
| **自由** | 不锁区域、编辑态也让权，方向键自由穿行全页（调试/非常规页面用） |

### 手机端按键

| 键 | 动作 |
|---|---|
| ↑↓←→ | 区域内空间导航；**长按**=连续移动（500ms 起跳，200ms 步进） |
| OK | 激活当前控件（DOM 层直接 `click()`，UIA 层 Invoke/Toggle/Select，退回回车）；**长按 0.6s = Alt+Tab** |
| ↩ 返回 | Esc 关弹层/对话框；**长按 0.6s = Ctrl+Tab 切标签** |
| Tab ⇥ | 通用焦点导航兜底 |
| 区域 ◀ ▶ | 切换区域（当前默认隐藏） |
| 模式 | 智能 → 区域 → 自由 循环（当前默认隐藏） |
| ↩ 焦点 | 回到上一个焦点（可跨区回退） |

### 焦点框

蓝色 `#38A5FF`、2px 边框、圆角、柔和外发光、移动带插值动画；Win32 原生 layered 窗口绘制，**全程点击穿透、不抢焦点、无残影**；按显示器 DPI 缩放（per-monitor v2），多显示器各自算。它跟的是**语义焦点矩形**，不是鼠标坐标。

### 启用网页语义层（推荐）

网页语义层需要浏览器调试端口，普通方式启动的浏览器没有：

1. 手动启动带调试端口的浏览器，例如：
   ```powershell
   & "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$env:TEMP\kzq-chrome-debug" --no-first-run --no-default-browser-check "https://www.google.com"
   ```
2. 确认端口就绪：`curl http://127.0.0.1:9222/json/version`
3. 之后在这个浏览器窗口里操作，方向键走 DOM 语义层

不开也能用：服务自动走 UIA 层，行为一致（区域锁、同行约束、编辑态让权都生效），只是控件名字没有 DOM 那么准。

**浏览器闪退排查**：

- 同一个 `--user-data-dir` 只能被一个 Chrome 实例占用。上次开着的窗口没关就再启动，新的会立刻退出——先关掉旧窗口。
- 目录路径含中文/特殊字符也可能导致参数解析失败，必要时把项目移到纯英文路径。

### 站点 Profile

`site_profiles.py` 内置 7 个站点档案：**ChatGPT / Gemini / X / YouTube / Google 搜索 / 哔哩哔哩 / 抖音**，各自定义区域选择器、默认区域、输入区功能组顺序、链接允许区、弹窗选择器。未命中的站点用通用 Profile（几何 + 语义兜底）。切站点自动换 Profile（CDP 连上后按真实 URL 重定，不靠窗口标题猜）。

**显示端**：**Tab 式选中效果框**——置顶青色边框（Win32 原生 layered 窗口绘制，点击穿透、不抢焦点、无残影），实时跟随当前焦点元素；每次移动同时把鼠标指针移到元素中心（悬停效果 + 位置指示）并注入 Ctrl 单按（浏览器叠加原生 focus ring）。再按一次「遥控模式」关闭并隐藏框。

技术参考：WICG Spatial Navigation (css-nav-1)、Remote Keyboard Navigation；手机端只发动作指令，全部几何计算在电脑端完成，网页（Chromium 无障碍树）与原生软件一套算法通吃。

**实测校准**（自建 fixture 网格 + Hacker News 真站实机跑出来的经验，全部有日志实证）：
- **内容区锁定**：Chromium 的 UIA 树是壳链结构（顶层 view_xxx Document 是空壳，真内容在深层 RootWebArea），且包含全部标签页——扫描根必须选「可见且与可视区交集最大（RootWebArea 加倍）」的 Document，否则方向键会逃逸进标签栏/地址栏/其他标签
- **verify 竞态**：Chromium 焦点更新异步，SetFocus 后立即读 HasKeyboardFocus 常拿到旧状态误判失败、试链跳到次优元素——40ms×3 重试后正常路径首次即命中
- **contenteditable 的 IsReadOnly=True 是 Chromium 语义怪癖**：只读滤网只用于网页根 Document，否则 GPT 聊天框这类编辑器全被误杀；空编辑器（无文本无 placeholder）在无障碍树里不存在，属浏览器现实
- **初始落点**用「视口内距窗口左上最近的候选」而非树序第一个（树序可能是浏览器注入的图片占位提示）

**UIA 层的响应速度与鲁棒性**（第一性原理：像 Tab 键一样跟手 = 「移动焦点」与「高亮刷新」解耦）：
- **快路径**：方向键请求只做 起点复用缓存焦点 → 几何计算 → SetFocus → 轻验证，立即返回（省掉同步等待与重读）
- **焦点追踪循环**：UIA 线程空闲时每 120ms 读一次焦点矩形刷新高亮边框——无论焦点被遥控、Tab 键还是程序移动都实时跟随；顺带刷新导航起点缓存与滚动补偿（同一元素矩形位移 = 页面滚动，候选缓存整体平移）
- **候选缓存**：遥控目标窗口 2 秒内的候选集直接复用，连按/连发单步零扫描；超时或该方向全落空才重扫
- **目标窗口锁定**：开启遥控时记录目标窗口 hwnd，后续扫描锁定该窗口——高亮浮层抢了"前台"也不会扫到自己
- **GPT 聊天框可达**：contenteditable 富文本框在 Chromium 上暴露成带 TextPattern 的 Group，同样收进候选
- **试链兜底**：每次取距离排序的前 6 个候选逐个 SetFocus 并读回验证，不可聚焦/已消失的自动落到次优；试链全失败且缓存是旧的则重扫再试一轮；`IsKeyboardFocusable=False` 的网页元素只降权不排除
- **大幅位移检测**：同一焦点元素位移 ≥80px = 虚拟列表回收/整页跳转，候选缓存标记过期，下次导航强制重扫（防聊天流刷屏后按旧坐标跳错）
- **视口内优先**（TV 遥控共识）：视口外候选加距离罚分，先在可视区里挑，挑不出才滚动翻页
- **滚动补偿**：每次焦点移动成功后现读焦点矩形，与候选缓存矩形之差即 SetFocus 引发的滚动量——候选缓存整体平移（固定定位的输入框在页面滚动时矩形不变，必须用元素自身对比才推得出来）
- **底部状态栏过滤**：贴窗口底缘的矮横条（状态条/托盘条）是 down 方向的几何死区，直接排除；<8px 的装饰元素一并排除

## 实时输入协议（锚定对账）

手机输入框是文本的唯一事实源：每条操作自带绝对锚点 `at`，服务端维护镜像缓冲，先按「锚点 − 当前光标」差值发方向键对齐，再删/注字。**单条请求丢失或乱序只影响那一条，下一条自动回正**，不会像旧方案（客户端猜电脑光标）那样一处竞态就永久发散。四种消息：`{at,del,ins}` 锚定编辑、`{at}` 光标定位（点手机文字移动电脑光标）、`{key,n}` 相对按键（空框滑动方向键/空框退格/回车）、`{reset}` 镜像归零。回车 = 提交：电脑端回车，手机框清空，两端镜像同步归零，直接打下一条。空框滑动能移光标靠的是「手势层」：空框时盖住输入框独占触摸（绕开浏览器原生光标拖拽和输入法手势），有字即摘。

**镜像坐标系**：镜像覆盖的范围是一个「岛」——聚焦预填后=整个电脑输入框，预填失败（UIA 盲区应用）时=手机打过的部分。相对按键（←/→/空框退格）可以把电脑光标移到岛外（负坐标=岛左侧前缀区、超长坐标=岛右侧后缀区），岛外删/注字对岛文本不可见、只挪光标账目；回车/翻页等无法建模的「盲键」会把岛作废，退化为原点跟随模式，重新点输入框时由预填重建。聚焦预填：任一层聚焦成功（含点按联动后的 `focus_read`）→ 服务端 UIA 读回电脑输入框全文 + **光标绝对位置（TextPattern）** → 手机框预填整段内容并定位到真实光标处（不抢电脑光标）；TextPattern 不可用时才 Ctrl+End 归位字段尾对齐原点。

**坐标单位 = 字形簇（用户感知字符）**：手机 JS 的字符串索引是 UTF-16 码元（1 个 emoji 占 2）、Python `len` 是码点、电脑端方向键/退格在 Chromium 系应用按字形簇移动——三套单位混用曾导致含 emoji 文本的光标系统性漂移。现协议统一：客户端发 `at`/`del` 前按 `Intl.Segmenter` 换算，服务端镜像算术一律按簇计数（`_g_*` 助手，覆盖 ZWJ/旗帜/肤色/keycap/CRLF），UIA 读回的 caret 偏移换算成簇索引入账、以规范化文本的 utf16 偏移返给手机端直接定位。失明后的首条锚定先 UIA 校准（`mirror calibrate`）再应用；整框镜像大跳落地后读回真实光标对账，方向键语义差异（Ctrl+Home 不一定=字段头）不累积。⌫ 按钮与读回清洗同理：零宽字符不再被改写、emoji 整簇删除。

**输入法直通**：手机流输入激活时，服务端把前台窗口的输入法切到英文直通（等效 Shift 切换，防拼音组合框吃掉注入的回车/方向键），静默约 2 秒后自动恢复原状态；`set KZQ_IME_ENGLISH=0` 可关闭。

**光标定位通道**（与手机框内容长度解耦）：① 点文字定位——预填（镜像=整框）后手机框里就是电脑输入框的全部内容，点到哪电脑光标到哪；每次 `pointerup` 都显式提交最终位置，同位置重复点击也会执行绝对定位；② 空框滑动/←/→ 长按——加速连发（32px≈1格起步，远滑幂次加速），无内容也不受限；③ 大跳——整框镜像下光标移动超过 80 格自动改用 Ctrl+Home/End 文档级锚点，几千字的长文定位也在毫秒级完成。**Win32 通道按控件实测 EM 坐标空间换算**（RichEdit 系换行算 1 字符、经典 Edit 算 2，首次使用探测一次并缓存，不再假设），读回与设置两端用同一空间换算，杜绝多行文本光标整体偏移。**UIA 直设光标（可读应用主通道）**：TextPattern Clone→Move→Select 直接落位（读回微调最多 3 轮+末次读回），设置前校验焦点原文与镜像一致，不一致即重建真实现状、绝不按旧坐标写入；UIA 连续超时自动熔断 5 秒，冷却期走 Win32/箭头快速通道，不再逐次等满超时卡顿。客户端以 `opCount/selGen/caretGen` 代数守卫丢弃过期读回（快照早于本次光标移动的结果作废），定位后的读回与周期对账保留手机光标，杜绝"点哪都跳回末尾"的回写竞态。

**输入静默期自动对账**（无需任何手动按钮）：打字停顿 600ms 且写链空闲时，UIA 静默读回电脑输入框与手机镜像比对——不一致（电脑端有框外改动）就自动采用电脑端现状，手机框刷新并提示「已自动同步」；手机输入框聚焦期间保留用户当前光标，不让读回反抢定位。对账读回不占用写链（慢 UIA 不堵打字/定位），用户 3 秒内有操作自动推迟巡逻；周期巡逻禁用剪贴板兜底（不做 Ctrl+A 全选闪烁），剪贴板通道只保留给显式聚焦/手动同步。只走 UIA，无感无闪烁；UIA 盲区应用连续读不到会自动退避（静默跳过），此时岛外内容靠加速连发/Home/End 定位（岛内点定位始终有效，不因读回失败而失效）。UIA 盲区应用（如 DSH 导航）在点手机框聚焦时自动走剪贴板通道同步电脑端内容（输入框会全选闪烁一次，剪贴板读取后自动还原），`set KZQ_CLIP_READBACK=0` 可关闭。

## 自动聚焦输入框

点手机输入框，电脑自动把键盘焦点放进目标应用的输入框。**五层兜底，按证据新鲜度排序**（物理点击 > OS 焦点 > 历史档案 > 结构启发 > 盲点，命中即停）：

0. **当前焦点/鼠标命中**（0 秒新鲜度，最高优先）：你的触控板点击刚落在哪个输入框，焦点就保留在哪——同页面切换输入框零成本，已学的档案不会把焦点抢回记录位置；鼠标命中测试（ControlFromPoint 向上找最近可输入祖先）在焦点读取失败时兜底；
1. **语义档案回放**：「📍 记录位置」学习当前焦点控件的语义特征（automation_id / 类名 / 名称 / 归一化矩形），聚焦时在前台窗口内匹配（阈值 180 + 与第二名分差 40，control_type 必须一致）——同一个输入框精准回放，不会聚焦到页面上别的框；
2. **记忆位置**：档案同时存点击位置（水平比例 + 垂直边距），语义失效或 UIA 盲区应用（微信 4.x）时回放；浏览器页面的仅位置档案**限定同一页面**（跨页自动失效并提示——位置是布局的投影，页面内容一变就过期）；
3. **UIA 通用打分 + 相邻动作语义**：扫描前台窗口找最像输入框的控件（Edit / Document / Group），词表三档（发送消息/输入内容/说点什么/创建任务/搜索…）+ 几何加权 +「已在用的输入框 +40」+ **相邻动作语义 +60**（输入框同一行紧挨着"发送/搜索/创建/提交"等按钮或图标时加分，连没有提示词的裸输入框也能靠旁边的发送图标认出来）；密码框、浏览器地址栏、只读网页根（Chromium 的 IsReadOnly Document）、网页根节点（rootwebarea）会被排除；
4. **兜底**：鼠标当前位置点击。

**档案身份 = 进程 exe + 站点 origin + 窗口类名**（第一性原理：窗口标题是意图上下文的坏代理——换对话/换项目标题就变，但"在这个应用的输入框说话"的意图没变）。浏览器窗口的站点 origin 从**地址栏**读取（浏览器 chrome 永远暴露在 UIA，不受网页无障碍树影响）——所以 ChatGPT 换项目/换对话窗口档案依然有效，而切到别的网站不会误用；原生/Electron 应用（如 DeepSeek Harness 桌面版）用 exe 身份，应用内换项目天然有效。

**键盘联动**（第二页开关）：开启后触控板「点按」时手机自动弹出键盘并聚焦输入框——点击同时发往电脑，直接打字。原理：点按手势内同步聚焦手机输入框（移动浏览器要求键盘弹出必须在用户手势内，Android/iOS 均可靠）；右键不触发。

「☰ 更多 第二页 → 输入框聚焦 → 📍 记录位置」学习流程：按一次进入学习 → 用触控板**点击**目标输入框 → 再按一次确认（自动采集焦点控件语义 + 鼠标位置，同一目标重学即覆盖）。第二页列表可管理/重录/删除档案。每次扫描写 top3 候选诊断日志，出问题能直接从日志定位。

「☰ 更多」为左右滑动翻两页：第一页 自定义 + 音量媒体 + 显示器 + 电源；第二页 输入框聚焦。

| 区域 | 功能 |
|---|---|
| 输入框 | **实时上屏（常开）**：打字/手机输入法语音，文字即时出现在电脑光标处，删改同步退格，不占电脑剪贴板；点输入框/点按联动时自动读回电脑输入框**全文+光标位置**预填——电脑上已有内容（含手机没打过的部分）也能删改和定位，且不抢电脑光标；Enter 即时发送（电脑回车提交，手机框同步清空），Shift+Enter 本地换行同步；空框滑动移电脑光标（加速连发） |

## 安全

- 服务端带随机 token，扫码 URL 里带 `?t=xxx`，局域网内其他人无 token 用不了
- 只监听局域网，关掉服务端即全部失效

```
set KZQ_DRYRUN=1

```

## 加自定义功能（示例）

两步：

1. `server.py` 的 `do_cmd()` 里加分支，例如切换到显示器输入源 HDMI：
   ```python
   if cmd == "monitor_hdmi1":
       run([r"C:\Tools\ControlMyMonitor.exe", "/SetValue", "Primary", "60", "15"])
       return "显示器切到 HDMI1"
   ```
2. `static/index.html` 命令区加一个按钮：
   ```html
   <button data-cmd="monitor_hdmi1">HDMI1</button>
   ```

常用备用命令：截屏到剪贴板 `run(["powershell","-Command","Add-Type -AssemblyName System.Windows.Forms; [Windows.Forms.Clipboard]::SetImage([Windows.Forms.Screen]::PrimaryScreen)"])`；休眠 `shutdown /h`；打开某程序 `run(["notepad"])`。

## 自定义快捷按钮

「☰ 更多 → 自定义」区域的按钮来自项目根目录的 `custom.json`，**改文件保存即生效，无需重启**。格式：

```json
[
  {"name": "微信", "type": "combo", "value": "ctrl+alt+w"},
  {"name": "记事本", "type": "run", "value": "notepad"},
  {"name": "AI平台", "type": "url", "value": "https://你的AI平台网址"},
  {"name": "浏览器", "type": "run", "value": "msedge"}
]
```

- `combo`：发全局热键（应用自带热键，如微信 `ctrl+alt+w`）；支持 ctrl/alt/shift/win/字母数字/F1-F12/方向键等
- `run`：启动程序或命令
- `url`：默认浏览器打开网址（会开新标签；想固定独立窗口可把 AI 平台装成 PWA 应用再用 `run` 启动）

**打开聊天框的完整流程**：点自定义按钮 → 目标窗口弹到前台（鼠标通常还停在上次输入框的位置）→ 点手机输入框（自动在鼠标位置点击聚焦）→ 打字。

## 常见问题

- **手机打不开页面**：确认同一 Wi-Fi；路由器开了「AP 隔离」会拦，关掉即可；防火墙放行 Python
- **🎤 按钮没出现**：浏览器不支持（http 局域网地址下 Chrome 可能禁麦克风），用输入法语音方案
- **关屏幕后马上又亮**：动鼠标或按任意键会唤醒，属正常
- **触控板太快/太慢**：调 `index.html` 里 `flush()` 无需改；移动灵敏度可把服务器 `moveRel` 坐标乘系数
